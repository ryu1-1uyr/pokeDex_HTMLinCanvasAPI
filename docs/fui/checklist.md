# FUI レビュー用チェックリスト

画面を作ったら、この表で採点してから次の改善を決める。
各項目 0（できていない）/ 1（部分的）/ 2（できている）。根拠は [principles.md](principles.md)。

## 採点表

| # | 観点 | 原則 | 問い |
| --- | --- | --- | --- |
| C1 | 物語 | P1 | すべての演出が「何をしている画面か」の一文に奉仕しているか |
| C2 | 主役 | P2 | 各画面の主役が 1 つに決まっていて、1 秒で目が行くか |
| C3 | 画面の識別 | P2 | どの画面が何の画面かを、中身を読まずに判別できるか |
| C4 | 一次モーション | P3 | 状態が変わるとき、変化の過程が見えるか |
| C5 | 二次モーション | P3 | 何もしていないときも、控えめに動き続けているか |
| C6 | 借りた文法 | P4 | 実在の計測器・UI の文法を、意味を保ったまま使っているか |
| C7 | 機能の設定 | P5 | 飾りの要素それぞれに「何を測る/指すか」の設定があるか |
| C8 | 色の役割 | P6 / grammar 1 | ink 中心で、warn は 1 箇所、データ色はチップだけか |
| C9 | 線と書体 | grammar 2-3 | 1px 基準、数値は等幅、角の規則が守られているか |
| C10 | 強調の手段 | grammar 1 | 強調を色や太さではなく光（発光）で表しているか |
| C11 | 視線誘導 | P2 | 状態が変わった後、主役に視線を戻す仕掛けがあるか |
| C12 | 奥行き | P4 / Hansen | 物理的な奥行き（筐体）と、情報の奥行き（レイヤー）があるか |

## 採点履歴

### 2026-10-27 — FUI ステップ 1〜3 実装後

| # | 点 | メモ |
| --- | --- | --- |
| C1 | 2 | スキャン・解析の物語に沿っている。流体シミュは削除済み |
| C2 | 1 | 主役は決まっているが、メイン画面は名前・説明文とアートワークが同じ強さで競合している |
| C3 | 0 | 画面の見出しがない。`BASE STATS` 以外は中身を読まないと判別できない |
| C4 | 2 | 起動・デコード・変身・ブラケット |
| C5 | 2 | 読み値・スイープ・レンズの呼吸 |
| C6 | 2 | レーダー、CRT、製図の引き出し線、レジストレーションマーク |
| C7 | 2 | 読み値ごとに設定あり（SIG = 受信強度、σ = ばらつき） |
| C8 | 1 | warn を定義したが未使用。注目点の表現がない |
| C9 | 2 | 1px、等幅数値、角の規則 |
| C10 | 2 | HDR ブルーム |
| C11 | 0 | 変身が終わった後、アートワークに視線を戻す仕掛けがない |
| C12 | 1 | 筐体の奥行きはあるが、UI レイヤー間の奥行きはない |

合計 17 / 24。次の改善: C3（パネル見出し）、C8（warn の極値表示）、C11（ロックオン照準）。
