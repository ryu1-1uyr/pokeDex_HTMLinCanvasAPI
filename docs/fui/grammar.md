# FUI 文法 — 再現のためのルールとトークン

[principles.md](principles.md) の原則を、そのまま実装に使えるルールに落としたもの。
数値はすべてトークン化し、CSS は `src/ui/fui-tokens.css`、シェーダーは各 `.wgsl` の定数に置く。
新しい値が必要になったら、まずここに追記してからコードに入れる。

## 1. 色の役割

色は「何色か」ではなく「何の役割か」で選ぶ。役割は 4 つだけ。

| 役割 | CSS | WGSL | 用途 |
| --- | --- | --- | --- |
| ink | `--fui-ink` `#b8fff0` | `INK` | 主要な線・文字・データ。画面の色の 9 割はこれ |
| ink-dim | `--fui-ink-dim` `#5fa797` | `INK * 0.5` 前後 | ラベル、単位、補助テキスト |
| line | `--fui-line` (ink 30%) | `INK * 0.1〜0.25` | 枠線、グリッド、区切り |
| warn | `--fui-warn` `#ffb547` | `WARN` | 注目・異常・極値。**1 画面に 1 箇所まで** |

- データ固有の色（ポケモンのタイプ色）は ink を置き換えない。7px の識別チップと、レーダーの塗りだけに使う。
- 強調は色を増やさず「明るさ（HDR でブルームさせる）」で表現する。

## 2. 線

- 基本は 1px。太さで階層を作らない。階層は明るさ（line → ink → 発光）で作る。
- グリッドなどの最下層は ink の 8〜22%。目盛りは 35% 前後。輪郭やアクティブ要素は 100% + 発光。
- 角: 筐体 28px、液晶のベゼル 14px（物理的なもの）。液晶の中の UI 要素は 0〜4px（デジタルなもの）。

## 3. 書体

| 用途 | 書体 | サイズ |
| --- | --- | --- |
| 日本語の主要テキスト | DotGothic16 | 本文 14〜15px、名前 34px |
| ブランド・英字ラベル | Chakra Petch | 11〜16px、字間 0.08〜0.15em |
| 数値・マイクロテキスト | Share Tech Mono | マイクロ 10px、ラベル 12px、値 15px |

- 数値は必ず等幅。桁が変わってもガタつかないことが「計測器らしさ」になる。
- 英字ラベルは大文字 + 字間広め。`//` や `·` を区切りに使う（例: `SYS.DEX // GEN-I // ID-0001`）。

## 4. 余白とグリッド

- 基本単位 4px。画面内側の余白 12/14/24px、マイクロテキストは角から 5〜6px × 12px。
- 十字マーク（レジストレーションマーク）は画面の角から 8px。
- 主役の周辺に情報を置くときは、主役に重ならない「外周の帯」に置く。

## 5. モーション

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--fui-snap` | 280ms `cubic-bezier(0.2, 0.9, 0.2, 1)` | 選択ブラケットなど、吸着する動き |
| `--fui-draw` | 450ms `cubic-bezier(0.6, 0, 0.2, 1)` | 引き出し線など、線が引かれる動き |
| `--fui-fade` | 300ms `ease-out` | テキストの出現 |
| decode | 300〜700ms（文字数に比例） | 文字のデコード |
| boot | 開始 0.35s、画面ごとに +0.25s、各 0.55s | 起動シーケンス（シェーダー `BOOT_*` と CSS `--boot` を一致させる） |
| morph | 1.45s | パーティクル変身（`particles.wgsl` の `END` と `ArtMorph.ts` を一致させる） |
| 二次モーション | 更新 10Hz、スイープ 0.18 回転/秒 | 揺れる数値、レーダースイープ |

- 一次モーションは「速く始まって、ゆっくり止まる」。吸着・描画は ease-out 寄りにする。
- 複数要素は 0.15〜0.25s ずつずらす（スタッガー）。同時に動かすと処理の手順が見えない。
- 二次モーションの振幅は小さく。主役の一次モーション中は目立たないこと。

## 6. レイヤー順

奥から手前へ。新しい要素はどの層に属するかを先に決める。

1. 背景（草むら、ぼかし） — `scene.wgsl` `fsBg`
2. 筐体（プラスチック、ボタン、レンズ） — `composite.wgsl` シェル分岐
3. 液晶のバックプレーン（ドットマトリクス、グラデーション）
4. データ可視化（レーダー、目盛り、十字マーク） — シェーダー、HDR で発光可
5. DOM テキスト・SVG（ラベル、マイクロテキスト、引き出し線）
6. 表面効果（ホロ、走査線、ガラスの映り込み）
7. 起動マスク・ブルーム

- オーバーレイモードでは 5 が CSS で最前面に来るため、6 と 7 は DOM にかからない。
  HTML-in-Canvas モードでは 5 もシェーダーを通るので、上の順がそのまま成立する。

## 7. 奥行き（視差）

画面の中の層に「ガラス面からの深さ」を与え、筐体が傾いたときに深さに比例してずらす。
ずれ量 = 深さ × `-view.xy / view.z`（`view` は筐体の座標系での視線）。

| 層 | 深さ | 実装 |
| --- | --- | --- |
| HUD（照準、引き出し線） | -40px（ガラスより手前） | CSS `--fui-depth-hud`、`--fui-px` `--fui-py` |
| フォーカス中のパネル（HTML-in-Canvas のみ） | -28px（浮き上がり、判定も追従） | `Panels.ts` `LIFT` |
| DOM テキスト | 0（ガラス面） | クリック判定と一致させるため動かさない |
| データ可視化（レーダー、十字） | 7px | WGSL `DEPTH_DATA` |
| 液晶の背面（ドットマトリクス） | 30px | WGSL `DEPTH_BACKPLANE` |
| ベゼル内壁（見た目のみ） | 40px | WGSL `WALL_DEPTH` |

- **奥行きは誇張しないと伝わらない。** 物理的に正しい数 px の深さでは、最大傾きでも 1px 未満しか動かず誰も気づかない。
  クリック判定に関わらない層（HUD、背面、内壁）は思い切って深くする。
- クリック判定に関わる層（DOM）は動かさない。ずらしたい場合は、判定を持たない装飾だけを別の層に分ける。
