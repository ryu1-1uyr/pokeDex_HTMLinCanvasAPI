# FUI パターン集

再利用できる演出の型。各パターンは「目的（どの原則に効くか）/ レシピ / 実装場所 / 注意」で書く。
原則は [principles.md](principles.md)、数値は [grammar.md](grammar.md) を参照。

## 情報レイヤー

### マイクロテキスト
- 目的: 情報密度で「本物のシステム」感を出す（P5）。
- レシピ: 画面の四隅に 10px 等幅の短い文字列。`SYS.DEX // GEN-I // ID-0001` のように区切り記号で構造化する。
- 実装: `src/ui/fui.tsx` `MicroText`、スタイルは `.micro`。
- 注意: 1 画面 2〜3 箇所まで。主役の領域に入れない。

### ライブ読み値
- 目的: 何もしていない時間にも動き続ける二次モーション（P3）と、機能の設定（P5）。
- レシピ: 設定を決めた値（受信強度、スキャン率、経過時間）を 10Hz で揺らす。揺れは 2 本の sin の合成で決定的にする（`wobble`）。
- 実装: `src/ui/fui.tsx` `LiveReadout`、`src/ui/fuiUtils.ts` `wobble` `clock`。
- 注意: 小さいコンポーネントに閉じ込めて、その部分だけ再描画する。

### 引き出し線（コールアウト）
- 目的: 主役に「解析している」設定を与える（P1, P4 製図の文法）。
- レシピ: 画像のアルファから特徴点（最上点、重心、最右点）を求め、点 → 斜め線 → 水平線 → ラベル。線は `stroke-dashoffset` で描き、ラベルは線の後にフェード。
- 実装: `src/ui/fui.tsx` `Callouts`。
- 注意: 線は `vector-effect: non-scaling-stroke` で常に 1px。

## 処理の手順

### CRT 起動
- 目的: 状態変化の過程を見せる（P3）、見慣れた文法の誇張（P4）。
- レシピ: 中央に明るい走査線 → 縦に開く。画面ごとに 0.25s ずらす。シェーダー側と DOM 側（`clip-path`）で同じタイミング。
- 実装: `composite.wgsl` `BOOT_*`、`dex.css` `@keyframes screen-on`。

### 文字のデコード
- 目的: データが「確定していく」過程（P1, P3）。
- レシピ: 確定済みの接頭辞 + ランダムなグリフ 6 文字を、左から右へ掃く。
- 実装: `src/ui/fui.tsx` `Decode`。

### 選択ブラケット
- 目的: 注目点を示す照準の文法（P4）。
- レシピ: 四隅の L 字（`linear-gradient` 8 本）を外側から吸着させる。
- 実装: `dex.css` `.list li[aria-selected='true']::after`。

### パーティクル変身
- 目的: 切り替えを「データの再構成」として見せる（P1）。
- レシピ: 前後の画像のピクセルを全単射で対応させ、上から順に組み上げる。飛行中は ink 色で発光。
- 実装: `src/gpu/ArtMorph.ts`、`particleSeed.wgsl`、`particles.wgsl`。

### ロックオン照準
- 目的: 状態変化の後に視線を主役へ戻す（P2）、照準器の文法（P4）、解析の物語（P1）。
- レシピ: 画像のアルファから外接矩形を求め、四隅の L 字を 1.5 倍から縮めて吸着させる。`TARGET LOCKED // ID` を 2 回点滅。引き出し線は照準が止まってから（`LOCK_TIME`）伸ばす。
- 実装: `src/ui/fui.tsx` `Callouts`（`.lock`）、`dex.css` `@keyframes lock-on`。
- 注意: 「変身 → ロック → 注釈」の順番そのものが手順の演出なので、同時に出さない。

### 主役を先に、文字は後に
- 目的: 状態が変わった直後に、目が主役だけに向くようにする（P2、チェックリスト C2）。
- レシピ: 「変身 → ロックオン → プロフィールのデコード」を順番に出す。ロックが終わるまでプロフィールは薄い `ANALYZING` のプレースホルダー。補助テキスト（説明文）は ink-dim で一段小さく、主役の列を広く取る。
- 実装: `Dex.tsx` `profileId` / `ready`、`fuiUtils.ts` `LOCK_TIME`、`dex.css` `.profile.analyzing`。
- 注意: プレースホルダーも同じ DOM 構造で出すと、確定時にレイアウトが跳ねない。

## グラフィックの文法

### 奥行きレイヤー
- 目的: 情報に奥行きの階層を持たせる（Jayse Hansen の HUD、チェックリスト C12）。
- レシピ: 層ごとに深さを決め、傾きに応じて深さ × 視線の傾きだけずらす。シェーダーの層は `parallax(depth)`、DOM の層はレンダラーが毎フレーム渡す `--fui-px` `--fui-py` を CSS の `translate` で使う。
- 実装: `composite.wgsl` `DEPTH_*`、`Renderer.ts` `updateTilt`、`dex.css` `.callouts`。
- 注意: 深さは誇張する（grammar §7）。クリック判定を持つ DOM は動かさない。

### パネル見出し
- 目的: どの画面が何かを 1 秒で読ませる（P2、チェックリスト C3）。
- レシピ: 色を反転した番号ブロック `01` + タイトル + 右へ消えるヘアライン。番号は画面の読む順。
- 実装: `src/ui/fui.tsx` `PanelHeader`、`.panel-head`。

### 警告色の極値
- 目的: warn を「1 画面 1 箇所」のルールで使い、注目点を作る（grammar 1）。
- レシピ: 種族値の最大値だけ、シェーダーの頂点を WARN で発光 + リング、ラベルを warn 色にして `PEAK` を付ける。同値は先頭を採用し、シェーダーと DOM で同じ規則にする。
- 実装: `composite.wgsl` `radar()`、`Dex.tsx` `peakIndex`。

### 目盛りリング
- 目的: 計測器らしさ（P4）。
- レシピ: 円 + 10° ごとの短い目盛り、30° ごとに長い目盛り。
- 実装: `composite.wgsl` `radar()`。

### レジストレーションマーク（十字）
- 目的: 画面の「枠」を設計図のように見せる（P4）。
- レシピ: 画面の角から 8px に、腕 4.5px の十字。ink 45%。
- 実装: `composite.wgsl` 画面分岐。

### HDR ブルーム
- 目的: 強調を色ではなく光で表現する（grammar 1）。
- レシピ: 発光要素だけトーンマップ後に加算して 1 を超えさせ、ソフトニーのしきい値で抽出、5 段のデュアルフィルタでぼかす。
- 実装: `src/gpu/Bloom.ts`、`bloom.wgsl`。
